# 项目模块 · 可交互原型

入口：左侧「项目」，或本地开发服务的 `/?view=projects`。

## 设计依据

沿用目录中的《画衣衣 UI 视觉规范》《画衣衣 3.0 UI 视觉执行标准》及现行 `src/styles/tokens.css`：钴蓝单强调、灰阶分层、无投影、胶囊按钮与 Tab、语义化颜色、系统字体。早期《画衣衣视觉规范》的蓝紫双强调和投影不再采用。项目布局借鉴用户提供的 WorkBuddy 截图，未改造原有设计端其他模块。

## 本次实现

- 项目列表：搜索、客户开发 / 自主开发 / 归档筛选、新建和编辑。客户与品牌可不关联，客户可多选。从共用的本机档案中选择，按稳定编号关联，尚未接入正式 CRM。
- 概览：目标、客户、品牌、任务 / 资产 / 交付计数、待人工处理任务、近期资产、留言与动态、可逆的归档标记。
- 任务：一个项目多个对话，保存创建时的项目配置和所引用资产版本；记录后续消息、状态、示例产出及人工上传成果。
- 资产：分类、来源筛选、卡片 / 列表、真实文件上传与下载、预览、上传修订、显式采用版本、引用到新任务、选入交付。
- 交付：文档与款式汇集、内部选款、面辅料 / 样衣说明、凌迪 Cloud 链接、分客户推款记录及反馈、内部确认与模拟 PLM 交接。
- 项目配置：项目指令、专家团、技能与拟接入连接器。技能和专家团选项复用平台现有定义。

## 关键规则

1. 新版本不会自动采用。采用新版本后，交付工作清单使用新版本；既有客户推款和内部交接仍保留原快照。
2. 客户反馈、任务完成、选入交付、内部选款「保留」都不是最终内部确认。
3. 交接时至少包含一个「保留」款，并勾选内部核查确认；本次所选文件版本、面辅料说明和 3D 链接形成固定快照。
4. 交付是项目内部的成果视图，没有另建方案包管理模块。推款记录也留在项目中。

## 原型边界

- AI 回复及演示产出是明确标注的模板 / 既有示例图，无真实生成或外部搜索。工作稿支持人工编辑及真实 HTML / PPTX 导出；任务快速演示产出为 Markdown 草稿。
- 未接入真实客户库、连接器授权、团队协作、权限审批、PLM 或 Cloud API。Cloud 功能为用户填写分享链接后打开；客户推款记录不实际发消息。
- PLM 为模拟交接，不会创建真实样衣开发单。下载的交付清单 / 快照是 JSON 目录，非包含文件本体的压缩包；文件可单独下载。
- 元数据：`localStorage / hyy-odm-projects-v1`。文件：`IndexedDB / hyy-odm-project-files-v1`，单文件最大 30 MB。只存当前浏览器；清理浏览器数据会丢失记录，需保留原文件。
- 只读保护：元数据解析失败时不覆盖原始内容；保存失败时提示且保留旧记录。内部确认人是演示录入，不代表真实身份或权限校验。

## 客户、品牌与项目串联

- 左侧「客户」：轻量档案、联系人 / 负责人、常用品类与开发要求、资料原件、关联品牌 / 项目，以及从项目汇总的推款反馈。不另建商机、销售漏斗或审批流程。
- 左侧「品牌库」：新增「品牌档案」视图；「原有资产库」保留厂商原组件及交互。品牌记录定位、客群、风格、价格带、开发注意事项、资料与关联客户。
- 项目选客户后优先推荐关联品牌，同时允许选择其他目标品牌。不会因选品牌自动绑定客户，也不会因移除客户自动移除品牌；竞品品牌仍应作为参考资料。
- 客户 / 品牌详情可发起预填关联的新项目；项目概览可反向进入档案。推款与反馈只在项目维护，客户页提供汇总与跳转。
- 创建任务时明确勾选客户 / 品牌摘要和文件，不默认读取整份档案；联系人不进入背景摘要。任务保留创建时摘要与文件引用快照，后续档案更新不修改历史任务。

档案元数据使用 `hyy-odm-directory-v1`，文件复用现有 IndexedDB。项目的 `customerIds` / `brandIds` 为关联依据，`customers` / `brands` 保留为兼容显示名称；客户改名时推款记录仍保留当时名称，并通过 `customerId` 或旧名称别名关联到当前档案。

旧版本项目中的自填名称会兼容导入档案，并在保存编号关联前先持久化档案。名称和历史名称做同类型去重；暂不提供删除档案，避免破坏项目与历史记录。保留字段与 ID 是为后续对接正式客户系统准备，并不代表已经打通真实数据。

## 模板与 ODM 协作能力（2026-09-20）

本批在原有四个 Tab 内补充模板创建和能力调用，不增加强制流程。

| 形式 | 首批定义 | 职责 |
| --- | --- | --- |
| 8 个技能 | 客户 Brief 拆解、内外部相似款检索、内外部面辅料检索、趋势分析报告、服装企划 PPT、款式设计与改款、款料匹配建议、交付资料核查 | 输入和输出明确的单项工作 |
| 4 位专家 | 客户需求专家、趋势企划专家、服装设计专家、面辅料专家 | 专业判断，可组合调用技能 |
| 3 个专家团 | 趋势企划专家团、款式驱动开发专家团、材料驱动开发专家团 | 多个专业角色协作，展示成员及可调用技能 |
| 平台功能 | 项目、档案、资产、画布、下载与修订、内部选款、交付和最终确认 | 持久化对象、确定性操作与权限边界，不包装成 AI 技能 |

### 项目模板

- 5 个预置模板：客户需求开发、自主款式开发、材料驱动开发、趋势研究、服装企划。
- 项目列表「从模板创建」或新建弹窗下拉选择；预填指令、技能、专家、专家团和拟接连接器。
- 名称、客户、品牌、季节、品类由用户填写，不复制客户资料、历史任务或资产。客户仍然可不关联或关联多个。
- 已编辑指令或能力时，应用另一模板需确认；替换范围不含基本信息和客户品牌关系。未确认时禁止提交。取消不会丢失原配置。
- 专家与专家团分字段保存。历史项目中已知的厂商团队从 `experts` 兼容移入 `teams`，历史任务快照不改。
- 本批仅提供预置模板；没有实现自定义模板的保存、发布或共享。

### 任务调用

- 「调用技能 / 专家 / 专家团」打开分类选择面板，项目已配能力优先展示；支持本次临时调用，不修改项目默认配置。
- 展示所需输入、预期成果、人工确认点、拟用数据源；专家团还展示成员和技能。
- 每次调用保存能力定义、本次要求及明确勾选的项目资产版本，可在对话中途追加调用；不自动读取全库。
- 可生成明确标注的 Markdown 演示工作底稿，归入原任务、原项目；沿用下载、本地修改、上传修订和择优交付操作。不会冒充真实 PPT、真实检索结果或 AI 设计。

## 任务工作区与成果回流（2026-09-21）

继续沿用「概览、任务、资产、交付」四个 Tab。以下工作区从任务对话或能力调用记录进入，不增加独立导航、不强制按阶段执行。

### 搜款搜料 → 原设计画布

- 分别选择款式 / 面辅料、内部 / 外部 / 全部，输入描述并可附参考图。当前内部检索是项目资产与标注示例库的关键词匹配；参考图只记录检索条件，尚未做视觉相似度匹配。
- 一次检索保存为任务结果集，保留条件、来源、选中项及历史。结果不自动进入资产，支持 2–4 项对比、择优归档；重复归档去重。
- 外部服务未连接时不伪造结果；可手动上传已取得的参考文件，注明平台 / 供应商、来源链接和说明。选择「全部」当前只返回可用的本地候选。
- 选中的参考图片可进入厂商原设计画布。支持保存画布草稿、刷新后继续编辑，以及把选定图实际导出 PNG，归回原任务的项目资产。
- 保存草稿不等于归档成果；同一画布图再次归档会新增修订，不自动替换已采用版本。画布内原有 AI 操作仍是厂商演示。

### 款式与面辅料

- 款式资产详情可从项目面辅料中选料，记录主料 / 辅料 / 备选料、部位 / 用量、供应商及备注。
- 关联固定当时的材料版本。材料后续更新会提示复核，不自动替换款式选料。
- 关联进入交付内容及内部确认快照；继续保留自由填写的开发说明和凌迪 Cloud 3D 样衣分享链接。

### Brief、趋势报告和企划 PPT

- 任务内分别提供三类工作稿，支持编辑段落 / 页面、排序、引用资产、保存和人工确认。同一任务同一类共用一份工作稿。
- 从能力调用进入的新工作稿带入该次调用的要求和指定资料版本。已有工作稿不因再次调用被覆盖；引用可人工补充。
- Brief 确认后，可主动「设为项目需求」。概览展示当前已确认内容；此后新任务带入快照，历史任务不变。修改 Brief 会取消本稿确认，但不会静默覆盖项目已确认需求。
- 趋势报告 / Brief 导出真实 HTML 文件，带段落、参考图与来源；企划导出真实 PPTX，文字与图片可分别在 PowerPoint 编辑，并非整页截图或改后缀的 Markdown。
- 当前是人工编辑加模板排版，不会自动阅读资料、分析趋势或生成结论。未填写完整的段落会明确保留「待补充」，稿件确认不代表内容已完整、客户认可或 PLM 放行。
- 导出后归档到原任务资产，支持下载、本地修改、上传新版本、人工采用，再选入交付。重复导出同一稿件新增修订。
- HTML 预览使用空权限 sandbox 和限制性 CSP，禁止脚本及外部资源请求；下载原文件不改变内容。长报告含内嵌图片时不截断 HTML。

### 技术验证与待接入边界

- 新增检索 / 画布 / 款料链路测试 22 项、工作稿测试 22 项；原有四套测试 94 项回归。测试使用独立浏览器上下文，不修改用户已有数据。
- 真实 PPTX 经 LibreOffice 打开并转为 PDF，已检查封面与内容页；中文字体、图文布局正常。顺带修正快速提示组件误移除 iframe 可访问标题的问题。
- 项目模块 TypeScript 构建及局部 ESLint 检查通过。原厂商画布保留既有的热刷新导出 lint 错误与 Hook 依赖告警，本批未扩大修改范围。
- PPTX 生成库按需加载，文件仍保存在本机 IndexedDB；单文件上限 30 MB。没有服务器共享存储、多人并发控制或账户权限。
- 安装依赖后生产依赖审计提示 3 项高危：既有 lodash，以及 pptxgenjs 传递依赖 image-size 和其上游标记。pptxgenjs 的 browser 配置排除了 image-size，当前只嵌入 PNG / JPEG，未启用其 Node 图片解析路径；这不等于完成安全整改，正式部署前需单独处理依赖审计。未执行可能破坏原系统的大版本强制修复。

生产接入仍需：真实 AI 执行、内外部搜索及以图检索、MCP 授权、凌迪 Cloud / PLM 接口、交付原文件打包与成员权限。客户反馈始终不能替代内部最终确认。

## 演示体验补齐（2026-09-25）

本轮只完成前端原型，继续使用既有 UI 规范，不新增后端或强制业务流程。

1. **公共资料与项目复用**：左侧「资产」进入公共资料；上传趋势报告、供应商材料册等，维护来源、季节、客户及品牌。项目「资产」可引用公共资料，项目成果可沉淀回公共资料；客户 / 品牌详情可查看关联资料。跨项目复用只演示当前浏览器的数据共享。
2. **统一能力入口**：左侧「技能」展示技能、专家、专家团、连接器；ODM 定义和原平台能力共用目录。可加入项目配置，或直接在选定项目发起任务；项目配置及任务选择器读取同一目录。保留原厂商技能管理入口。
3. **对话执行演示**：Brief、趋势企划、搜款搜料三种场景展示「确认方向 → 进度 → 暂停 / 重试 → 预览 → 归档」。文档可继续编辑，搜索进入候选工作区；全程标注演示模式，不假装调用真实 AI。

建议演示路径：公共资料 → 引用到项目 → 任务中调用专家团 → 确认方向 → 预览成果 → 归档并修改 → 在交付中人工选取。

本轮不扩展对客展示页面，也不做交付原文件打包；内部最终确认规则保持不变。
